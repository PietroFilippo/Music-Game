Tray menu and the Desktop section of Settings

The tray menu is native: Windows draws it, so only its items, order and labels are specified. The Settings sheet gains two groups at the end, after Sounds: This computer (desktop build only) and Progress (both builds, so a browser user can export before switching to the desktop app).

Export progress…

  • Desktop: native save dialog, default name musicgame-progress-2026-10-15.json. Browser: a download of the same file.
  • Contents: { version, exportedAt, language, scores, attempts }: the musicgame.scores and answer-history keys verbatim, nothing else (no settings, they are per device).
  • Confirmation: the hint line updates to “Last export: …”; no toast.

Import progress…

  • Open dialog filtered to .json; validate the version and shape before touching storage.
  • Then a ConfirmDialog: “Import 12 plays across 5 topics?” with the note “Added to what is here. Best scores keep the higher value; answer history is merged by date.” Cancel / Import.
  • Merge, do not replace: the user may have practised on both devices. “Replace everything” is intentionally not offered; Stats already has Reset all.
  • Errors name the cause: “This file is not a musicgame export.” / “This export is from a newer version. Update the app first.”

Start with Windows

  • Registers a Run key via tauri-plugin-autostart with --tray, so start-up is silent: tray icon only, no window.
  • The toggle reflects the real registry state on open, not a cached preference, so a change made in Task Manager shows correctly.
  • The tray note under it is static copy; it is the only place that explains the Close-to-tray behaviour besides the one-time toast.
